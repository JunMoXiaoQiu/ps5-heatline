About
Shows
FPS now, frametime, CapFrameX's real-time metrics over 20 s (average, P1, P0.2, 1% and 0.2% low), stuttering time over 5 s, session average / min / max / duration, the game's title ID and name, and with More metrics on: percentiles, lows, stutters, time below a target and the frametime graph.
Read from
The console's own timestamp of every displayed frame (/dev/dce, offset 0x20), read every 4 ms, only while a game runs. Game name: /system_data/priv/appmeta/<ID>/param.json (or param.sfo, /user/appmeta). Context GAME / OS: the kernel log.
Data structure
Display driver request 0x80308217 on /dev/dce (0x30-byte argument: selector 0x10000000A, mask, output pointer). In the answer: 0x08 = frame (flip) counter, used; 0x20 = time of the last frame on the CPU timestamp counter, used (converted with sceKernelGetTscFrequency); 0x18 = the same moment in microseconds and 0x38 / 0x40 / 0x48 = other timestamps, used only if 0x20 stops moving; everything else is not decoded. Game name: localizedParameters.defaultLanguage → titleName in param.json (other languages ignored), or the TITLE key of param.sfo. Frame times are exact (console clock, µs); 2+ frames between two reads share their time equally (counted as merged); frames over 250 ms are pauses. Not available on PS5: GPU / CPU busy time (PresentMon).
Data path
fps.c keeps the last 32,768 frame times in a ring and recomputes the metrics once per second → /api → game. More metrics are only computed while switched on (saved as /data/heatline/fps_more); the frametime graph reads /fps/ft only while it is open.
Formulas
All written out in the table below.
Accuracy
Frame times: exact to the microsecond (the console's own timestamps). Metrics: rounded to 0.1 like CapFrameX, shown as integers like its overlay. "FPS now" is a one-second summary. When 2+ frames fall between two reads (rare at 4 ms), their total time is exact but is shared equally between them.
CSV columns
Credits
CapFrameX: every real-time formula, window and default, taken from its source code (OnlineMetricService, FrametimeStatisticProvider); MathNet.Numerics: the R-8 quantile CapFrameX uses; PS5 Monitor: the GAME / OS context method.

Frame times. Every frame is timed with the console's own timestamp of when it was shown, read every 4 ms from the video output. fti = duration of frame i in ms, fpsi = 1000 / fti. When 2+ frames are shown between two reads they share the measured time equally (their sum stays exact).

Real-time window (CapFrameX defaults). W = the frames of the last 20 s (a frame leaves when tnewest − ti > 20 s); n = number of frames in W. If no frame comes for more than 2 s, W starts again empty. Recomputed every second.

Quantile Q(x, τ) (MathNet R-8, the library CapFrameX uses), on values sorted ascending x1 … xn: h = (n + 1/3)·τ + 1/3; if ⌊h⌋ < 1 → x1; if ⌊h⌋ ≥ n → xn; else x⌊h⌋ + (h − ⌊h⌋)·(x⌊h⌋+1 − x⌊h⌋).

About
Shows
CPU temperature, SoC channel 0, the highest of SoC channels 1–7, CPU and GPU power, their sum, CPU and GPU voltage and current, fan speed.
Read from
sceKernelGetCpuTemperature; sceKernelGetSocSensorTemperature channels 0–7; sceKernelGetSocPowerConsumption (8 rails, each with mW, mV and mA); sceKernelGetCurrentFanDuty.
Data structure
sceKernelGetCpuTemperature: one int, °C, used. sceKernelGetSocSensorTemperature(channel): one int, °C per channel; 0–7 used, what 1–7 measure is unknown; above 7 never read (0–64 crashed the kernel on FW 13.60). sceKernelGetSocPowerConsumption: 0x70-byte block = 28 × u32. Words 0–23 = 8 rails × {mW, mV, mA}: rail 0 (follows the GPU) and rail 1 (follows the CPU, measured with a CPU-only on/off test) used; rails 2–7 only in the CSV (2–3 rarely change: frozen for 28 s in the menu in one test, unchanged for 6 minutes in a game in another; 4–7 read 0). Words 24–27 not used (ps5-hwinfo's guesses: temperatures, an EDC limit, a peak). sceKernelGetCurrentFanDuty: u16 duty 0–1024, used as % = duty / 1024 × 100. Voltage and current are the console's own numbers, not checked with a meter.
Data path
Read by the payload on every /api request (each page refresh) → cpu_temp, soc, power_mw, volt_mv, cur_ma, fan_raw. Min / max are kept by this browser since the page was opened.
Formulas
CPU + GPU = rail 0 + rail 1. SoC max = highest of channels 1–7. Power = mW / 1000, voltage = mV / 1000, current = mA / 1000.
Accuracy
Temperatures: whole °C. Power, voltage, current: as reported (1 mW, 1 mV, 1 mA steps), never checked against a meter, hence "approx." / "reported". Fan: duty in 1/1024 steps, shown to 0.1 %. Min / max: since this page was opened.
CSV columns

About
Shows
CPU clock setting, GPU clock, CPU usage (average and each of the 16 threads).
Read from
sceKernelGetCpuCoreClock (highest of the 8 cores); sceKernelGetSocClock word 20 (GFXCLK); sceKernelGetCpuUsage and the time of the idle threads SceIdleCpu0–15.
Data structure
sceKernelGetCpuCoreClock: 8 ints (MHz per core), highest used; it is the reported setting, not the live clock (a timed test measured 3070–3465 MHz while 2560 / 3200 was reported). sceKernelGetSocClock: 26 u32 clock domains; word 20 (GFXCLK) used, the only one that follows GPU load (correlation 0.97 with GPU power); word 25 reads the same, the others stay fixed. sceKernelGetCpuUsage: one 40-byte entry per thread (pid, tid, user time s+µs, system time s+µs); only the 16 idle threads SceIdleCpu0–15 are used (logical CPU 13 is named SceIdleCpuRv); the other ~1,400 threads are skipped. Threads 1 & 2 run on core 1, 3 & 4 on core 2, and so on.
Data path
Clocks are read on every /api request; usage is sampled once per second by cpuload.c → cpu_mhz, gpu_mhz, cpu_usage.
Formulas
Thread usage = 100 % − share of the last second spent in that thread's idle thread. Average = mean of the 16 threads.
Accuracy
Usage: from per-thread time counters (microseconds), averaged over 1 s, shown to 1 %. GPU clock: MHz as reported. CPU clock: the reported setting, not the live clock.
CSV columns
Help wanted
Wanted: a source for the live CPU clock (none found yet).

Display output
YCbCr 4:2:2
what the PS5 sends to the screen · every second

  

  

  
About
Shows
What the PS5 sends to the screen right now: resolution, refresh rate, HDR, VRR, colour depth, colour format and range. The amber "YCbCr 4:2:2" badge marks 4:2:2 mode (colour detail halved, used to fit HDR at 1440p 120 Hz).
Read from
sceVideoOutGetCurrentOutputMode_ for the main output (bus 0x7000), in libSceVideoOut, loaded once into Heatline. The normal function lookup refuses it on FW 13.60, so it is found with the payload SDK's kernel-side lookup by name. Read-only: no video handle is opened, nothing on screen changes; each call runs under a crash guard and reading stops for good if it ever fails.
Data structure
32-byte record. Bytes 0–3 = record size (always 32). Byte 4 colour format: 1 = RGB, 3 = YCbCr 4:2:2. Byte 5 range: 1 = limited, 2 = full. Byte 6 HDR: 2 = off, 13 = on with RGB, 14 = on with YCbCr 4:2:2. Byte 7 bits per pixel: 24 = 8-bit, 36 = 12-bit. Byte 8 refresh: 3 = 59.94 Hz, 13 = 119.88 Hz, 1 = 60 Hz with VRR. Byte 9: 0x80 = VRR on. Byte 16 resolution: 9 = 720p, 11 = 1080p, 15 = 1440p, 12 = 2160p (guess, no 4K screen to check). Bytes 10–15 and 17–23 always 0, 24–31 always 00 ff ff ff ff ff ff ff: not used. Not seen yet (shown as "unknown code N"): 4K, 50 Hz and other rates, YCbCr 4:4:4 / 4:2:0, 10-bit. All decoding checked by changing Video Output settings one at a time and against the monitor's own signal info.
Data path
display.c reads it every second (or at once with the refresh button), decodes the 32-byte answer → /api → display. A code that is not decoded yet is kept on the console with the game and every value of that moment (/data/heatline/display_unknown.jsonl, each combination once, last 100); open /display/log to read or copy them.
Accuracy
Exact: the console's own codes; a value is only shown when its code is decoded. Read every second, so a change can take up to 1 s to appear.
CSV columns
Help wanted
Wanted: 4K (2160p) screens, 50 Hz / 24 Hz / 40 Hz modes, YCbCr 4:4:4 or 4:2:0, 10-bit colour, other PS5 models. Open /display/log (every unknown code is kept there with the game and settings), or copy Raw data, and send it with the console's Video Output settings.
Credits
AnyPS5 contributors (the call, bus 0x7000 and the 32-byte record); shadPS4 (PS4 video codes, 3 and 13 match); Marice/ps5-exporter (kernel-side lookup by name and by ID); the decoding was measured on this console.

About
Shows
Console time and time zone, how far the clock is from internet time, last sync.
Read from
The console clock and sceKernelConvertUtcToLocaltime (time zone offset); internet time over SNTP (UDP 123): Cloudflare's numeric addresses first (no DNS needed), then time.cloudflare.com, pool.ntp.org, time.google.com.
Data structure
Clock: seconds since 1970 (UTC) and the offset from sceKernelConvertUtcToLocaltime, used. Accepted only from the server asked, dated 2000–2100; half the round trip is added; the time zone is never changed.
Data path
ntp.c checks or syncs only when asked (buttons), or once at start with "Sync automatically" (saved as /data/heatline/ntp_autosync) → /api → clock, ntp.
Accuracy
Clock shown to 1 s. After a sync the console clock is within about half the round trip of internet time (a few ms on a normal connection).

Round-trip time to your router and to the internet: last, average, min, max, jitter, lost tries.
Read from
The time a TCP connection takes to be answered (accepted or refused, both are one round trip), like a ping without needing raw network access. Router = the console's default gateway, ports 80, 53 or 443; internet = 1.1.1.1:443 (Cloudflare), or 8.8.8.8:443 (Google) if it does not answer.
Data structure
No data is read: only the time until connect() answers (accepted, or refused with ECONNREFUSED / ECONNRESET, both one round trip) or times out after 1 s (= lost).
Data path
netlat.c tries each target every 5 s with a 1 s timeout (= lost), only while the switch is on (off by default) → /api → lat.
Formulas
Over the last 12 tries (one minute): average, min, max; jitter = average change between two tries in a row.
Accuracy
0.01 ms steps; includes the PS5's own network stack and the server's time to answer a connection, so it reads a little higher than a ping. Statistics over the last 12 tries (1 minute).

About
Shows
The threshold, its unit, the home-screen threshold and the interval.
How it works
Heatline sets the temperature threshold the PS5's own fan driver uses. It does not set a fixed fan speed: the system still controls the speed, but starts speeding the fan up from this threshold. A lower threshold means a cooler, louder console; a higher one, a quieter, hotter one. The threshold is written again every interval. Range 30–90 °C (86–194 °F).
Data path
Saved on the console in /data/heatline/fan_control.ini (ps5-fan-control's keys) and applied again each time Heatline starts → /api → fanctl.
Data structure
/dev/icc_fan ioctl 0xC01C8F07 with a 10-byte buffer: byte 5 = threshold in °C, written; the other 9 bytes are always 0 (as in ps5-fan-control); nothing is read back. Settings file: ps5-fan-control's keys (enable, use_fahrenheit, target_temperature, xmb_target_temperature, show_status, interval).
Differences
From ps5-fan-control: nothing is written until "Fan threshold" is turned on here (ps5-fan-control applies 70 °C by default); nothing is written while a ps5-fan-control.elf process is running; the status notification is shown only after Save & apply, not every interval.
Accuracy
Whole °C; °F values are converted and rounded.
CSV columns
Not exported.

About
Shows
Theme, temperature unit (°C / °F, display only), measurements, refresh rate, history length, data tools.
Data path
Theme, refresh rate and history length are remembered by this browser only. The measurement switches are saved on the console (/data/heatline/lat_on, fps_more) so every browser sees the same.
Data structure
Browser settings: the browser's local storage (theme, refresh rate, history length, charts). Console settings: files in /data/heatline (lat_on, fps_more, fan_control.ini, ntp_autosync).
Accuracy
—
CSV columns
Export CSV writes one row per History point (raw: every kept point, empty cells where a value had no reading). Columns are grouped by topic: time, temperatures (°C and °F side by side), fan, game, CPU, GPU, power rails, RAM, network, display. The table under Data says where each column is on the page. Separator: , with a decimal point, or ; with a decimal comma for Excel in French (and other languages that write 1,5).
